可靠性与运维：保护只是第一步

2026-09-11 约 45 分钟 前置：Lesson 05

本课成果 · Win

你能拿出一份可靠性方案 + 运维要点清单：知道 PON 特有的安全风险在哪、 ONU 怎么认证、下行怎么加密、网管和光功率怎么监测、出了故障按什么顺序查。

Lesson 04给了你 Type B/C 保护， Lesson 05分了业务网。 但保护只解决"断链"，这课补上另外三件同样要命的事：安全、可管理、可运维。

01 可靠性是端到端的，不只是保护倒换

把"可靠"拆成五层，任何一层缺了都会成为单点：

层次要检查什么
设备冗余OLT 双主控、双电源、关键板卡冗余
链路冗余Type B / Type C 保护、双归属、核心交换机双机
电源双路市电 + UPS；ONU 侧是否需 PoF / 本地备电
环境机房空调、防雷接地、走线物理分离（主备不共管沟）
切换指标故障切换要多快？会不会断业务？
切换时间有标准答案

ITU-T G.984.1 第 14.3 节：T1/E1 业务要求 50 ms 的保护时间，GPON 应支持 50 ms 保护。 对传统电话业务，丢帧超过 120 ms 就会断话，需要重新呼叫。

实战参照：贵州省人民医院的全光网支持全链路保护 + 双归属冗余，切换 50 ms 内完成（Omdia 医院 FTTO 分析）。

02 PON 特有的安全风险：被改装的 ONU

这是全光园区最容易被忽略的一点，也是标准专门开一章（G.984.3 第 12 章）的原因：

PON 的下行数据是广播给该 PON 口下所有 ONU 的。如果有恶意用户重新编程自己的 ONU， 就可以监听到所有用户的下行数据——这就是"窃听威胁"，PON 安全机制正是为对抗它而设计。 （G.984.3 §12.1 大意）

看窃听威胁怎么发生：开启 AES 时下行是密文，"恶意 ONU"读不懂； 点按钮关闭 AES，它就能直接读取同一 PON 口下所有用户的下行数据。

风险说明
下行广播 + 合法 ONU 被改造同一个 PON 口下的其他用户可能看到你的下行流量
伪造 ONU 接入没有认证的话，陌生 ONU 可能被 OLT 误认并上线
管理面被盗用ONU 密码/注册 ID 泄漏后被冒充

两个对策：加密 + 认证

对策标准做法
下行加密AES-128、CTR 模式；密钥由 OLT 与 ONU 之间交换并定期切换（G.984.3 §12.2、§12.3/12.4）
ONU 认证基于序列号（SN）、PLOAM 密码、注册 ID（LOID）；也允许 MAC 地址入库等方式（G.984.3 附录 VI）
医院必做 内网跑的是患者隐私与诊疗数据，AES 必须开启；ONU 一律做认证，禁止"即插即用"式放行。 这两条写进方案与招标技术要求里，验收时逐条核对。

03 可管理：网管、OMCI 与光功率监测

全光园区"省心"的前提，是有一套能看见每个 ONU 的网管：

能力靠什么
OLT 远程管理 / 配置 ONUOMCI（ITU-T G.988）：业务模板、属性、告警、性能统计
统一网管统一平台管理 OLT / ONU，最好与既有以太网同一界面（见 L1 的提醒）
光功率监测读 ONU 收光 / OLT 收光；无源分光器本身不可管理，需要额外手段
告警LOS 失光、LOF 失帧、光功率越限、ONU 掉线
一个必须知道的运维难点 分光器是无源的、不可管理的。某条支路光衰变大或断裂时，网管只能看到"这个 ONU 掉线/收光低"， 定位到具体是哪一段需要 OTDR 或现场光功率测量。方案里要预留这个手段，否则故障会查很久。

04 可运维：一张三阶段的运维清单

阶段要做的事
开局规划（点位/分光比/预算）→ 施工（熔接、成端、标识）→ 验收（逐点测光功率、打业务）
日常监控告警 → 巡检光功率趋势 → 备份配置 → 管理 ONU 台账与认证白名单
故障先看网管告警（掉线/收光低）→ 判断是 ONU、跳纤还是 ODN → 现场测光/OTDR 定位 → 更换 → 复盘并更新台账

05 技能练习

回忆练习 · 写运维要点清单

不看上面，用自己的话写出这份清单（每项一句话）：

(a) 可靠性五层各要检查什么？
(b) 安全上必须做哪两件事？为什么？
(c) 开局 / 日常 / 故障三个阶段各做哪三件事？

(a) 可靠性五层：设备冗余（双主控/双电源）、链路冗余（Type B/C + 双归属 + 核心双机）、电源（双路市电 + UPS）、环境（空调/防雷接地/主备走线分离）、切换指标（GPON 应支持 50 ms）。

(b) 两件事：① 下行 AES 加密（CTR 模式、128 bit）——因为 PON 下行是广播，被改装的 ONU 可窃听他人数据；② ONU 认证（序列号 / PLOAM 密码 / 注册 ID）——防止伪造 ONU 接入。医院内网涉及患者隐私，两者都必须开。

(c) 三阶段：开局——规划、施工（熔接/成端/标识）、验收（逐点测光功率+打业务）；日常——监控告警、巡检光功率趋势、备份配置与 ONU 台账；故障——看网管告警判断范围、现场测光/OTDR 定位（分光器无源不可管）、更换后复盘更新台账。
