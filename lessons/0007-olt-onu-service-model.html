业务模型：一条业务是怎么"配"出来的

2026-09-11 约 45 分钟 前置：Lesson 06

本课成果 · Win

你能读懂一张 OLT 业务配置模型图——知道 OLT 板卡、PON 口、ONU 注册、T-CONT、GEM port、VLAN 各自在哪一层，一条业务从"光信号"到"上网"中间经过了哪些配置对象。

上一课说 OMCI（G.988）负责远程管理 ONU。 但 OMCI 到底在"配"什么？这一课把配置这件事拆开——先看懂模型，下一课才能动手配。

01 先认清硬件层次：配置"配在哪一层"

全光的设备层次比传统交换机多几层，配置前必须先对上号：

OLT 设备的层次
机框 / 子架
机箱本体，提供槽位与背板　有源 · 机房
↓
板卡
控制板 / 上行板 / PON 业务板　插在槽位里
↓
PON 口
板卡上的每个 PON 端口　一条 PON 口 = 一个 P2MP 域
↓ 光纤 + 分光器（无源）
ONU
光网络单元　有源 · 房间/终端
↓
业务口
ONU 上的网口 / 电话口 / Wi-Fi / 物联网口

记住这条对应关系：板卡 → PON 口 → ONU → 业务口。配置时说的"配在哪个口"，一定要问清是哪一层的口。

02 ONU 上线三部曲

ONU 从"插上光纤"到"能用"，标准里叫激活（activation），分三个阶段 [G.984.3]：

  1. 参数学习（parameter learning）

    ONU 学习上行开销参数（如均衡时延等），为后续通信做准备。

  2. 序列号发现（serial number acquisition）

    OLT 发发现请求，ONU 上报自己的 序列号（SN）。这一步就是配置里"注册/认证"的落点（用 SN、密码或注册 ID）。

  3. 测距（ranging）

    OLT 测量到 ONU 的距离/时延并补偿，保证不同距离的 ONU 上行不撞车。完成后 ONU 分配到一个 ONU-ID，正式上线。

配置时的对应关系 你在网管里"注册一个 ONU"，本质是在做第 2、3 步：认证它的身份（SN/LOID）、 让它拿到 ONU-ID。所以注册失败一般是 SN 填错、认证信息不匹配，或光功率不够。

03 核心：从 ONU 到业务，四个配置对象

ONU 上线后还上没有业务。要让它"能上网/打电话"，需要理解四个对象。这是全光配置的骨架：

对象标准定义 / 作用管什么
ONU-IDONU 在 PON 上的身份标识（激活时分配）身份
Alloc-ID / T-CONTT-CONT 是 ONU 内"承载流量、按上行带宽分配处理"的对象；默认 Alloc-ID 等于 ONU-ID上行带宽
GEM portGTC 适配子层上的抽象，代表一条客户端业务流的逻辑连接业务封装
service-port / 业务流把 GEM port 与业务 VLAN 绑定，让业务真正落地（厂商叫法不同）业务落地
一句话记住四层

ONU-ID 认身份 → T-CONT（Alloc-ID）管上行带宽 → GEM port 装业务 → service-port 绑 VLAN 落地。

两个容易混淆的点 ① Alloc-ID ≠ GEM port：前者是上行带宽分配用的，后者是业务封装用的，一个 ONU 可以有多个 Alloc-ID 和多个 GEM port。
② 默认 Alloc-ID 与 ONU-ID 相等，它承载上行 PLOAM 和 OMCI（OMCC）管理通道——所以它不能随便删。

04 DBA 与五种 T-CONT：为什么要有类型

DBA（动态带宽分配）是 OLT 根据各 ONU 的活动状态和配置的流量合约， 把上行 PON 容量分配给各 T-CONT 的过程 [G.984.3 §3.2.4]。 不同的业务要签不同的"合约"，于是有了五种 T-CONT 类型：

类型带宽特性适合的业务
Type 1固定带宽，不参与剩余共享对时延/抖动敏感：语音、TDM、部分监护
Type 2保证带宽，不参与剩余共享有明确速率上限的 on-off 业务
Type 3保证带宽 + 可参与非保证共享需要平均速率保证的突发业务
Type 4只参与尽力而为共享不敏感、突发型
Type 5其它类型的组合，通用大多数普通业务流的默认选择

来源：ITU-T G.984.3 (01/2014) 表 7-1。注意：T-CONT 类型只是方便引用"常见的 Alloc-ID 流量描述符组合"， 它的值不在 PON 接口上编码、也不发给 ONU。

映射到医院业务 语音/监护 → Type 1–2（要确定性）；影像/诊疗 → Type 3–4（要高吞吐）；办公/访客 → Type 4–5（尽力而为）。 这正是 L5 的 QoS 分层在配置层的落地方式。

05 一张图串起来：业务配置六步

  1. 板卡与 PON 口

    确认业务板卡在位、PON 口启用，光功率正常。

  2. 注册 / 认证 ONU

    用 SN 或注册 ID（LOID）认证，ONU 获得 ONU-ID 上线。

  3. 套用能力模板

    厂商通常用 line profile（T-CONT / DBA）与 service profile（GEM / QoS）预设能力，注册时绑定。

  4. 建 T-CONT / Alloc-ID

    为业务分配合约（选 T-CONT 类型），管上行带宽。

  5. 建 GEM port

    为业务建立封装通道，映射到对应 ONU 与 T-CONT。

  6. 建 service-port（绑 VLAN）

    把 GEM port 与业务 VLAN 绑定，业务落到 ONU 的业务口；再到核心侧放通对应 VLAN。

记住顺序 物理（板卡/PON 口）→ 身份（注册）→ 能力（模板）→ 带宽（T-CONT）→ 封装（GEM）→ 落地（service-port/VLAN）。 下一课就按这个顺序动手配。

06 技能练习

回忆练习 · 画出业务配置模型

先不看上面。用你的话写出这两件事：

(a) ONU 上线的三个阶段是什么？配置里的"注册 ONU"对应哪一步？
(b) 一条业务从 ONU 到落地，经过哪四个配置对象？再用六步写出配置顺序。

(a) 上线三阶段：参数学习 → 序列号发现（SN 上报）→ 测距（分配 ONU-ID）。"注册 ONU"对应序列号发现 + 测距：认证身份（SN/LOID）并让 ONU 拿到 ONU-ID 上线。

(b) 四个对象：ONU-ID（身份）→ T-CONT / Alloc-ID（上行带宽）→ GEM port（业务封装）→ service-port / VLAN（业务落地）。

六步顺序：① 板卡与 PON 口 → ② 注册认证 ONU → ③ 套用能力模板（line/service profile）→ ④ 建 T-CONT/Alloc-ID → ⑤ 建 GEM port → ⑥ 建 service-port 绑 VLAN，并在核心侧放通。
