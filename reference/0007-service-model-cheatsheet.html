OLT/ONU 业务模型速查

一手来源：ITU-T G.984.3（TC 层）· G.988（OMCI）

01 硬件层次

层次说明
机框 / 子架机箱本体，提供槽位与背板
板卡控制板 / 上行板 / PON 业务板，插在槽位
PON 口板卡上的端口；一条 PON 口 = 一个 P2MP 域
ONU用户侧设备（有源）
业务口ONU 上的网口 / 电话口 / Wi-Fi / 物联网口

02 ONU 上线三阶段（G.984.3）

阶段做什么
① 参数学习ONU 学习上行开销参数（如均衡时延）
② 序列号发现OLT 发发现请求，ONU 上报序列号（SN）——对应"注册/认证"
③ 测距测量并补偿时延，分配 ONU-ID，ONU 正式上线

03 四个核心配置对象

对象作用管什么
ONU-IDONU 在 PON 上的身份（激活时分配）身份
T-CONT / Alloc-ID上行带宽分配对象；默认 Alloc-ID = ONU-ID，承载 PLOAM + OMCC上行带宽
GEM port代表一条客户端业务流的逻辑连接业务封装
service-port / 业务流把 GEM port 与 VLAN 绑定，业务落地业务落地

一句话：ONU-ID 认身份 → T-CONT/Alloc-ID 管上行带宽 → GEM port 装业务 → service-port 绑 VLAN 落地。

04 T-CONT 五种类型（G.984.3 表 7-1）

类型带宽特性适合
Type 1固定带宽，不参与剩余共享时延/抖动敏感（语音、TDM）
Type 2保证带宽，不参与剩余共享有速率上限的 on-off 业务
Type 3保证带宽 + 可共享非保证带宽需平均速率保证的突发业务
Type 4仅尽力而为共享不敏感、突发型
Type 5其它类型组合，通用大多数普通业务流

DBA（G.984.3 §3.2.4）：OLT 根据各 ONU 活动状态与流量合约，把上行容量分配给各 T-CONT。T-CONT 类型的值不在 PON 接口编码、也不下发 ONU。

05 业务配置六步

  1. 板卡与 PON 口：业务板在位、PON 口启用、光功率正常
  2. 注册/认证 ONU：SN 或 LOID，拿到 ONU-ID 上线
  3. 套用能力模板：line profile（T-CONT/DBA）、service profile（GEM/QoS）
  4. 建 T-CONT / Alloc-ID：选类型、定带宽合约
  5. 建 GEM port：业务封装，映射到 ONU 与 T-CONT
  6. 建 service-port 绑 VLAN：业务落到业务口，核心侧放通 VLAN
